# Dolphin Group

Корпоративный сайт Dolphin Group: Next.js 16, React 19, TypeScript, Tailwind CSS 4.

## Локальный запуск

```bash
npm install
npm run dev
```

Сайт: `http://localhost:3000`.

## Контактная форма и Resend

Скопируйте `.env.example` в `.env.local` и заполните серверные переменные. Если уже есть `.env`, можно использовать его. Оба файла исключены из Git; `.env.local` имеет приоритет.

- `NEXT_PUBLIC_SITE_URL=https://dolphingrouptech.com` — публичный адрес для SEO. Локально допустим `http://localhost:3000`. Форма всегда отправляет запрос на относительный `/api/send`.
- `RESEND_API_KEY` — ключ Resend с правом отправки. Никогда не добавляйте префикс `NEXT_PUBLIC_` и не сохраняйте ключ в `.env.example`.
- `RESEND_FROM_EMAIL=Dolphin Group <website@dolphingrouptech.com>` — отправитель на подтверждённом домене Resend.
- `CONTACT_TO_EMAIL=dolphingrouptechus@gmail.com` — получатель заявок; задаётся исключительно на сервере.

Добавьте `dolphingrouptech.com` в Resend → Domains и внесите предложенные DKIM/SPF/MX-записи для **sending** в DNS домена. Дождитесь `Verified`. Приём входящей почты в Resend для этой формы не нужен. Не заменяйте существующие MX-записи основного домена: используйте ровно имена записей, которые показывает Resend (в том числе поддомен Return-Path).

До подтверждения домена можно локально тестировать с `RESEND_FROM_EMAIL=Dolphin Group <onboarding@resend.dev>`. Resend разрешает этому отправителю доставку только на адрес владельца аккаунта. Для реальной проверки используйте явную тестовую заявку и согласованный адрес.

При развёртывании задайте эти переменные в настройках хостинга и выполните повторное развёртывание. Нужен Node.js/serverless runtime, а не статический экспорт. Ротация ключа выполняется в Resend; новый ключ записывается только в локальный env или секреты хостинга. Если ключ попал в шаблон или журнал, отзовите его и выпустите новый.

## Поведение и защита

- Сервер проверяет типы, длины, выбранную услугу, её дополнительные поля, email/телефон и обязательное согласие.
- Только same-origin JSON-запросы; размер тела ограничен 24 КиБ; есть honeypot.
- Отправитель и получатель не принимаются из запроса. Письмо содержит plain text; email посетителя используется как Reply-To, номер телефона остаётся в тексте.
- Успех возвращается только при получении ID от Resend. Ошибки сервиса не показывают внутреннюю диагностику посетителю; поля сохраняются при сбое.
- Таймаут Resend — 12 секунд, браузера — 20 секунд. Повтор той же заявки использует тот же idempotency key. Обновление страницы начинает новую попытку.
- Базовый лимит: до 5 валидных попыток для одного контакта и до 30 суммарно за 10 минут **на процесс**. Лимиты сбрасываются при перезапуске и не разделяются между serverless-инстансами. Для публичного запуска включите постоянный лимит `/api/send` на уровне хостинга/WAF; при росте нагрузки добавьте общее хранилище лимитов или CAPTCHA.
- Подтверждение Resend означает принятие письма сервисом, а не гарантию попадания во входящие. Проверяйте статус доставки в Resend → Emails.

## Проверки

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

Тесты используют подмену отправки и не отправляют настоящие письма. Проверяются валидация, ошибки провайдера, инъекции, лимиты, размер запроса и идемпотентность. Контрольные скриншоты — в `artifacts/`.

Документация: [Next.js + Resend](https://resend.com/docs/send-with-nextjs), [подтверждение домена](https://resend.com/docs/dashboard/domains/introduction), [idempotency keys](https://resend.com/docs/dashboard/emails/idempotency-keys).
